\begin{abstract}
Long-running LLM agents periodically \emph{compact} their context, replacing history with a summary. The four harnesses we examined (Claude Code, the Anthropic API, the OpenAI Responses API, and Gemini CLI) all trigger compaction at a fixed token count or a fixed fraction of the context window. We cast compaction \emph{timing} as a rent-or-buy problem under real prompt-cache pricing. Carrying history costs cache-read ``rent'' on every call. A compaction is a one-time ``buy'': the summary's output tokens, a cache rewrite of the new prefix, and any re-fetch of dropped state.

In steady state the problem is the Economic Order Quantity. The cost-optimal compaction point $H^\star=\sigma+\sqrt{2gA/h}$ depends on growth per call, summary size and prices, but not on the context window. Because the cost curve is flat near $H^\star$, triggers within $2\times$ of it are near-optimal, while window-relative triggers become increasingly wasteful as windows grow.

We measure the model's parameters on headless Claude Code. Compaction leaves about 11k tokens regardless of history, and re-fetch of dropped content is negligible. With these parameters, $H^\star$ for our sessions is about 118k tokens of history. That makes Anthropic's 150k API default near-optimal, while compacting near a 1M window costs about 20\% more per session in trace-calibrated simulation.

An online rule that estimates growth and solves for $H^\star$ stays within 1.3\% of the best threshold tuned in hindsight across 17 dataset, price and window settings (25 Claude Code sessions; 1{,}500 sampled SWE-agent trajectories). A single fixed threshold tuned once loses up to 13\% when prices or summary costs change.

In an 18-run real-agent pilot, compacting early raised the bill by 32--143\%. Replaying each run's measured growth through the cost model reproduced its bill to within 7.9\% mean absolute error.
\end{abstract}

\section{Introduction}
Agentic coding assistants run sessions of tens to hundreds of model calls, and their context grows with every tool result. Harnesses therefore \emph{compact}: they summarize or drop history so the session can continue. \emph{What} to keep has been studied extensively~\cite{complexitytrap,acon,tracer,compactiontheory}. \emph{When} to compact has received little formal treatment, though cache-aware systems touch on it~\cite{tokenpilot,cliff,infercept}.

In the products we examined the trigger is a constant~\cite{docs}:
\begin{itemize}
\item Claude Code compacts near the window limit (about 967k on 1M-window models), and its CLI rejects windows below 100k.
\item Anthropic's compaction API defaults to 150k tokens.
\item OpenAI's Responses API exposes a \texttt{compact\_threshold}.
\item Gemini CLI's documented default is 70\% of the window.
\end{itemize}

The bill, however, is set by prices, growth, and how much a compaction costs. Prompt caching makes held history cheap (0.05--0.1$\times$ input price) but not free. Each compaction pays output price for the summary and rewrites the cached prefix, at 2$\times$ input price for 1-hour cache entries.

We make the following contributions.
\begin{enumerate}
\item \textbf{A cost model of compaction timing under prompt caching} (\S\ref{sec:model}), with its parameters measured on Claude Code.
\item \textbf{An EOQ characterization} (\S\ref{sec:theory}).
  \begin{itemize}
  \item A closed-form, window-independent optimum, extended to the case where dropped state is re-fetched.
  \item Flatness, which bounds the cost of any mis-set trigger.
  \item The consequence that window-relative triggers grow increasingly wasteful as windows grow, and that no single threshold is robust across pricing regimes.
  \end{itemize}
\item \textbf{Online rules.}
  \begin{itemize}
  \item The ski-rental break-even rule tracks $H^\star$ to within $2b/h$ calls with no knowledge of growth.
  \item An online steady-state rule that matches the hindsight-tuned threshold.
  \item A cold-cache rule for compacting when an idle gap has expired the cache.
  \end{itemize}
\item \textbf{Evaluation} (\S\ref{sec:eval}).
  \begin{itemize}
  \item Trace-calibrated simulation against product defaults and an offline optimum.
  \item Empirical worst-case ratios.
  \item A real-agent pilot that drives Claude Code with an external \texttt{/compact} controller and validates the cost model against real bills.
  \end{itemize}
\end{enumerate}

\section{Related work}

\paragraph{What to keep.}
\begin{itemize}
\item Observation masking matches LLM summarization on SWE-agent at about half the cost~\cite{complexitytrap}.
\item ACON optimizes compression guidelines~\cite{acon}.
\item TRACER learns per-tool retention~\cite{tracer}.
\item ARC replaces tool outputs with recoverable citations~\cite{arc}.
\item Context-Folding learns to branch and fold~\cite{folding}.
\item MemGPT pages memory under model control~\cite{memgpt}.
\item Tirmazi et al.\ relate compaction to one-way communication complexity~\cite{compactiontheory}. Their analysis concerns the content of a bounded state, not timing or price.
\item Liu finds that compression increases re-fetching~\cite{compresscost}. That effect is our $\rho$, which is negligible for Claude Code on our tasks.
\end{itemize}

\paragraph{Cache-aware context management.}
\begin{itemize}
\item TokenPilot trades context sparsity against prefix-cache stability with lifecycle-based eviction~\cite{tokenpilot}.
\item CliffCompaction truncates rather than rewrites history~\cite{cliff}.
\end{itemize}
Neither derives when a compaction pays for itself.

\paragraph{Online algorithms.}
\begin{itemize}
\item Ski rental~\cite{karlin88,karlin94} and its learning-augmented variants~\cite{purohit18}.
\item The Bahncard problem~\cite{fleischer}.
\item InferCept's preserve, discard or swap decisions for KV cache during tool calls~\cite{infercept}.
\end{itemize}
Our steady-state analysis is the Economic Order Quantity of inventory theory~\cite{harris}.

\section{Cost model}\label{sec:model}

\paragraph{Notation.} All costs are in units of the base input-token price.
\begin{itemize}
\item \emph{Prices:} cache reads cost $r$, cache writes $w$ ($1.25$ for 5-minute entries, $2$ for 1-hour entries), and outputs $o\approx5$.
\item \emph{Session state:} a session has a static prefix $S$ and history $H$, which grows by $g$ tokens per call on average.
\item \emph{Holding cost:} holding one history token for one call costs $h=r+q$, where $q$ is an optional context-rot price.
\item \emph{Compaction:} compacting at $H$ leaves $s(H)=\sigma+\rho H$, made of a post-compaction conversation $\sigma$ and re-fetched state $\rho H$.
\end{itemize}

The buy cost is
\begin{equation}
K(H)=r(S+H)+o\sigma+(w-r)\,s(H)+P,
\end{equation}
where $P$ is an optional quality penalty.

\paragraph{Measured parameters.} We drove Claude Code (Sonnet 5.5) through 34 compactions.
\begin{itemize}
\item $\sigma\approx 11$k, roughly independent of $H$: post-compaction sizes ranged from 9k to 15k.
\item $\rho\approx 0.001$: tool outputs re-read after a compaction, for files or commands already seen before it, came to 0.1\% of the dropped tokens.
\item Claude Code writes 1-hour cache entries, so $w=2$, and Sonnet 5.5 reads cache at $r=0.05$.
\end{itemize}
We use $S=40$k, $\sigma=11$k and $\rho=0$ unless stated.

\section{Theory}\label{sec:theory}

\begin{proposition}[Optimal compaction point]\label{prop:eoq}
Suppose $\sigma$ is constant and a session compacts at $H$ and regrows over $n$ calls. Then $H=(\sigma+gn)/(1-\rho)$, and the trigger-dependent cost per call is
\[
f(n)=\frac{hgn(1+\rho)}{2(1-\rho)}+\frac{A'}{n},\qquad A'=rS+o\sigma+P+\frac{w\sigma}{1-\rho}.
\]
Minimizing gives
\[
n^\star=\sqrt{\frac{2A'(1-\rho)}{hg(1+\rho)}},\qquad H^\star=\frac{\sigma+gn^\star}{1-\rho}.
\]
For $\rho=0$ this is $H^\star=\sigma+\sqrt{2gA/h}$ with $A=rS+(o+w)\sigma+P$. In every case $H^\star$ does not depend on the window.
\end{proposition}

At Claude Code prices, $H^\star\approx 58$k at $g=700$ tokens per call (our pilot) and $\approx 118$k at $g=3.6$k (our sessions). The closed form agrees with a numerical minimization of the exact steady-state cost to within 2\% across all price regimes, $\rho\in\{0,0.1,0.3\}$, and $g$ from 500 to 8k (unit-tested).

\begin{proposition}[Flatness]\label{prop:flat}
$f(xn^\star)/f(n^\star)=(x+1/x)/2$.
\end{proposition}

\begin{corollary}[Window-relative triggers]\label{cor:window}
A trigger at fraction $\tau$ of the window has $x\approx(\tau W-S-\sigma)/(H^\star-\sigma)$, so its steady-state excess grows linearly in $W$. At Claude Code prices with $g=3.6$k, compacting at 967k gives $x\approx8.6$, or $4.4\times$ the optimal controllable cost. At $g=700$ it gives $x\approx19.5$ ($9.8\times$). The 150k API default gives $x\approx0.93$, which is essentially optimal. Finite sessions cap the realized excess, because a session that ends before the trigger fires never pays it.
\end{corollary}

\begin{proposition}[No robust fixed threshold]\label{prop:robust}
For a fixed threshold, $x=(H_0-\sigma)/(H^\star-\sigma)$, and $H^\star-\sigma\propto\sqrt{A/h}$. If $A/h$ spans a factor $F$ across the regimes a product serves, then every fixed threshold has $\max(x,1/x)\ge F^{1/4}$ in some regime. Its excess there is at least $(F^{1/4}+F^{-1/4})/2$.
\end{proposition}

\begin{proposition}[Break-even tracks the optimum]\label{prop:be}
Let $\sigma$ be constant and $\rho=0$. The ski-rental rule compacts once the accumulated rent on the compactable excess, $h\sum_k (H_k-s(H_k))$, reaches $K(H)$. It fires at
\[
n_{BE}=(b/h-\tfrac12)+\sqrt{(b/h-\tfrac12)^2+(n^\star)^2}\;\le\;n^\star+2b/h,\qquad b=r\le h,
\]
that is, within about two calls of $n^\star$, without knowing $g$.
\end{proposition}

For $\rho>0$ we report break-even's behavior empirically. We do not claim worst-case competitive ratios for the multi-cycle problem, because the buy cost rises over time and rent continues after each buy. Instead we measure empirical ratios against an offline optimum.

\begin{proposition}[Cold-cache rule]\label{prop:cold}
After an idle gap longer than the cache TTL, not compacting rewrites $S+H$ at price $w$. Compacting instead reads $S+H$ once uncached for the summary, pays $o\sigma$, and writes $S+s$. Compaction is therefore immediately profitable when
\[
(w-1)(S+H)>o\sigma+w(S+s)+P.
\]
With our measured parameters this means $H>118$k for 1-hour entries and $H>436$k for 5-minute entries.
\end{proposition}

\section{Evaluation}\label{sec:eval}

\paragraph{Data.}
\begin{itemize}
\item \textbf{Claude Code sessions.} 25 of our own sessions, reduced to numeric token usage only: 1{,}465 calls, mean growth 3.6k tokens per call, a median of 32 calls per session, and 94.6\% of input tokens served from cache.
\item \textbf{SWE-agent trajectories.} 1{,}500 trajectories sampled from 13{,}287 in two public shards~\cite{nebius}: mean growth 491 tokens per call. Token counts are approximated as characters divided by 4, and summaries are assumed to be 2k tokens, since these contexts peak near 10k.
\end{itemize}

\paragraph{Baselines and policies.}
\begin{itemize}
\item Fixed 92\% of the window, the reference for every reported change.
\item The product defaults: 150k of total context and 70\% of the window.
\item Deterministic break-even.
\item The online rule: Proposition~\ref{prop:eoq} solved numerically with a running estimate of $g$, with no tuning to the data.
\item The best fixed threshold, chosen in hindsight from an independent 48-point grid on the evaluation data.
\item An offline optimum, computed by beam DP over compaction times.
\end{itemize}
Price rows labeled ``Claude Code'' use $w=2$ but do not simulate cache expiry except in the cold-cache experiment.

\paragraph{Results} (Table~\ref{tab:main}).
\begin{itemize}
\item \textbf{The online rule matches the hindsight-tuned threshold to within 1.3\%} in all 17 settings, and is up to 1.2\% better than the best grid point on SWE-agent.
\item \textbf{Where the savings are.} Savings concentrate where window-relative triggers sit far above $H^\star$. Against the 92\% trigger:
  \begin{itemize}
  \item 20.5\% at a 1M window with Claude Code prices, and 21.4\% when replaying our 25 real sessions;
  \item 37\% with 0.1$\times$ caching at 1M;
  \item 27--65\% without caching.
  \end{itemize}
\item \textbf{Where they are not.} At a 200k window with Claude Code prices, every trigger is within 0.7\% of the best, because 92\% of 200k is already close to $H^\star$. Likewise the 150k API default nearly matches the online rule at our sessions' growth. For slow-growing SWE-agent sessions under Claude Code prices, no trigger matters by more than about 1\%.
\item \textbf{Robustness.} A threshold tuned once (83k, optimal for 0.1$\times$ caching) costs $+9.7$ to $+13.4\%$ when a quality penalty is added or caching is removed. The online rule stays within 0.1--0.8\% of the per-regime best throughout (\texttt{results/transfer.txt}).
\item \textbf{Summary size.} As summaries vary from 2k to 20k, the online rule beats the 150k default by up to 8.5\% (\texttt{results/sensitivity\_summary.txt}).
\item \textbf{Worst case.} Over every prefix of 150 adversarial sessions, break-even and the online rule stay within $1.15\times$ of the offline optimum. The 92\% trigger reaches $1.50\times$ at 1M, and a 30k threshold $1.80\times$ (Table~\ref{tab:worst}).
\item \textbf{Cold-cache rule.} With idle gaps at our measured rate (1.5\% of gaps exceed an hour), adding Proposition~\ref{prop:cold} to the 92\% trigger cuts its cost by 16\% at 1M under 1-hour caching. The online rule gains less than 0.2\% from it, because it keeps contexts small.
\end{itemize}

\paragraph{Real-agent pilot.}
We drive Claude Code (Sonnet 5.5) headlessly through 13- or 25-message sessions.
\begin{itemize}
\item \textbf{Task.} Twelve standard-library modules each carry one injected bug, reported vaguely one message at a time. The long variant adds twelve test-writing requests.
\item \textbf{Ground rules.} Rules stated only in the first message (tag every changed line; create no files in \texttt{pkg/}) probe whether compaction drops instructions.
\item \textbf{Recall probe.} A final request asks for each fix's original buggy expression, which is irrecoverable once the bug is fixed.
\item \textbf{Scoring.} Hidden differential tests against the untouched originals.
\item \textbf{Controller.} The CLI rejects compaction windows below 100k, so an external controller sends \texttt{/compact} between turns whenever its policy fires.
\end{itemize}
Table~\ref{tab:pilot} reports the results. In summary:
\begin{itemize}
\item \textbf{The economic arm behaved identically to \emph{auto}.} Its trigger, about 60k of history computed online, was never reached.
\item \textbf{Premature compaction is expensive.} Compacting whenever history exceeded 15k raised cost by 32\% and 143\%.
\item \textbf{Recall was lower after many compactions:} 9.7 vs.\ 11.7 of 12 after about nine compactions. With $n=3$ and one uncompacted run also at 10, this is suggestive, not significant.
\item \textbf{Cost-model fidelity.} Replaying each run's observed growth and compaction points through the cost model reproduces its reported cost with 7.9\% mean absolute error. The error is systematic: uncompacted runs are underpredicted by 9.3\% on average and compacted runs overpredicted by 5.1\%.
\end{itemize}
The pilot does not demonstrate savings from the economic rule, because no session grew past $H^\star$.

\section{Implications}
\begin{enumerate}
\item \textbf{Set triggers from economics, not window size.} $H^\star$ (Fig.~\ref{fig:hstar}) depends on growth, summary size and prices, not the window. At 1M windows, near-limit triggers cost about 20\% more per session in our traces (Fig.~\ref{fig:flat}).
\item \textbf{Today's 150k API default is about right for Claude-priced coding agents with $\sim$11k summaries.} It should move as $\sqrt{g\,A/h}$ when growth, summary size or cache tier change. The online rule does this automatically.
\item \textbf{Do not compact early.} Each compaction costs a summary call plus a cache rewrite, and in our pilot premature compaction raised bills by 32--143\%.
\item \textbf{With 1-hour caching, compact when an idle gap expires the cache} once history exceeds about $118$k.
\end{enumerate}

\section{Limitations}
\begin{itemize}
\item Quality enters the simulation only through re-fetch and a per-compaction penalty.
\item The pilot is small (18 runs), uses one model and one synthetic task family, and never exceeded $H^\star$.
\item The local traces come from one user.
\item SWE-agent token counts and summary sizes are approximations.
\item Idle gaps are modeled as Bernoulli.
\item The offline optimum is a beam-search approximation.
\end{itemize}
